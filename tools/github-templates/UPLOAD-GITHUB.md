# Что загрузить в GitHub

## Репозиторий: исходный код

Откройте **эту папку** в GitHub Desktop как новый локальный репозиторий, затем
сделайте первый commit и **Publish repository**. Либо используйте Git CLI:

```text
git init
git add .
git commit -m "Initial release v{{VERSION}}"
```

Далее свяжите локальный репозиторий со своим репозиторием на GitHub и выполните push.
Адрес репозитория и учётную запись выбирает владелец; в процессе подготовки
удалённый репозиторий не создавался и публикация не выполнялась.

В Git должны попасть `src`, `tests`, `tools`, `docs`, OCR-модели, файлы решения,
lock-файлы, настройки NuGet, `README.md`, `LICENSE`, `.gitignore` и `.gitattributes`.
Выбранная владельцем лицензия собственного кода — **MIT**; сторонние компоненты
сохраняют свои лицензии.

`.gitignore` исключает EXE, DLL, bin/obj, `.packages`, личные JSON, записи,
диагностику и локальные `.nupkg`. Не используйте `git add -f` для этих файлов.
Пакеты физически включены в комплект для офлайн-сборки, но это восстановимые
зависимости, не исходники. В клонированном репозитории используйте сборку без `-Offline`.
Для больших файлов загрузка через GitHub Desktop/Git удобнее веб-формы.

## Releases: готовая программа

Откройте **Releases → Draft a new release**, задайте тег **v{{VERSION}}** и прикрепите
**`{{EXE}}`** из этой папки. Для пользователя достаточно только этого одного файла.
Он включает runtime, OCR, модели, лицензии и автоматически извлекает служебные файлы.
Контрольная сумма готового EXE находится в `SHA256SUMS.txt`.

Готовый файл не подписан сертификатом издателя. На другом ПК может понадобиться
Visual C++ Redistributable x64: https://aka.ms/vs/17/release/vc_redist.x64.exe.
Основные клавиши и ограничения распознавания описаны в `README.md`.

## Проверить сборку

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\test.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\build-release.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\verify-release.ps1
```

В исходном комплекте с локальными пакетами первые две команды также поддерживают
`-Offline`. В GitHub-клоне пакеты нужно восстановить онлайн. Проверка EXE использует
изолированные тестовые данные, не изменяя пользовательскую статистику.
