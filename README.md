# Счётчик сундуков Fortnite для Windows

Прототип 0.2.0: отдельное приложение распознаёт уведомление об открытии сундука
в небольшой выбранной области экрана и считает появления этого уведомления.
Поддерживаются надписи `СУНДУК` и `CHEST`, проверка начисления XP, счётчик
поверх игры, ручные поправки, сохранение статистики и столбчатый график по дням.

## Быстрый запуск

1. На **Windows 10/11 x64** скачайте однофайловый релиз
   **`FortniteChestCounter-v0.2.0-win-x64.exe`** и положите его в удобную папку.
   Старый вариант с папкой тоже поддерживается: полностью распакуйте
   `FortniteChestCounter-Windows-x64.zip`.
2. Запустите EXE. .NET и Python отдельно устанавливать не нужно: .NET, OCR,
   русская/английская модели и лицензии включены в однофайловый релиз.
   Для ZIP запускайте `FortniteChestCounter.exe` внутри распакованной папки.
3. В Fortnite выберите режим экрана **«Оконный без рамки»**. В этом режиме
   захват изображения и отдельное окно счётчика работают поверх игры.
4. В окне счётчика выберите монитор с игрой и язык интерфейса.
5. Перейдите в игру, откройте сундук и, **пока видны название и начисление XP**,
   нажмите **Ctrl+Alt+F7**. На замороженном кадре выделите мышью небольшую область,
   содержащую название сундука и строку `+… XP` / `+… ОП` / `+… ОПЫТА`.
   Не включайте список заданий, чат, инвентарь и подсказки взаимодействия.
6. Нажмите **Ctrl+Alt+F8** для начала подсчёта. На следующих сундуках проверьте,
   что число увеличивается один раз на одно уведомление.
7. Перед следующим матчем нажимайте **Ctrl+Alt+F11**. Это обнуляет только
   счётчик текущего матча; дневная и общая статистика сохраняются.

Первый сундук, использованный для выбора области, мог исчезнуть до запуска.
При необходимости добавьте его вручную через **Ctrl+Alt+F9**.

Для распространения достаточно **одного скачанного EXE**, без соседних DLL
и моделей. При первом запуске он сам извлекает служебные файлы в приватный
кэш `%TEMP%\.net`; повторный запуск использует этот кэш. Настройки и статистика
по-прежнему находятся в `%LOCALAPPDATA%\FortniteChestCounter`, отдельно от кэша.
Одновременно можно запустить только одну копию счётчика: перед переходом
с папочной сборки на однофайловую закройте прежнее окно обычным способом.
На ПК без Visual C++ Runtime может потребоваться официальный Redistributable,
как описано ниже. Подготовка файла для GitHub: [docs/GITHUB-RELEASE.md](docs/GITHUB-RELEASE.md).

## Клавиши

Все сочетания используют **Ctrl+Alt** и работают при свёрнутом окне приложения.

| Клавиша | Действие |
| --- | --- |
| F7 | Выбор области на замороженном кадре выбранного монитора |
| F8 | Старт / пауза распознавания |
| F9 | Добавить один сундук |
| F10 | Отменить последний сундук текущего матча |
| F11 | Начать новый матч |
| F12 | Показать / скрыть счётчик поверх игры |

Те же действия доступны кнопками. Если сочетание занято другой программой,
окно покажет, какие именно клавиши не зарегистрированы.

## Настройка распознавания

- По умолчанию анализируется только активное окно с `Fortnite` в заголовке
  и процессом игры; редактор с названием проекта больше не считается Fortnite.
  При переключении на рабочий стол счётчик показывает «Ожидание Fortnite».
- Для небольшого уведомления обычно достаточно интервала **200 мс**.
  Более узкая область уменьшает нагрузку и посторонний текст.
- Оставьте включённой проверку XP: одного слова «сундук» недостаточно для
  надёжного отличия открытого сундука от подсказки или задания.
- Фильтр яркого текста выделяет белые, жёлтые и фиолетовые буквы. Если
  диагностика не видит текст, поставьте распознавание на паузу и попробуйте
  выключить фильтр или выбрать область заново.
- При изменении разрешения, масштаба интерфейса или расположения игры
  заново выберите область. Настройки распознавания меняются на паузе.
- В поле диагностики показаны текст и уверенность OCR для последнего кадра.
- В 0.1.2 при неудаче SparseText используется запасной SingleBlock: это помогает
  не пропускать мелкое название сундука рядом с крупной суммой XP.
- В версии 0.1.1 ошибки чтения ОП как `0п` / `0n` принимаются только вместе
  с близким `+число` и русским названием СУНДУК. Сырой текст диагностики при этом
  может оставаться ошибочным; цифры XP не переводятся в количество сундуков.
- Положение оверлея выбирается из четырёх углов. Он пропускает клики в игру.

## Что именно считается

Это **подсчёт экранных уведомлений**, поэтому точность зависит от того,
что показывает конкретный режим Fortnite, и от качества распознавания.
Программа требует два последовательных распознавания и ждёт исчезновения
уведомления не менее чем на 900 мс, чтобы не считать один сундук много раз.

Если несколько сундуков открыты очень быстро и их уведомления слились в одно,
прототип может засчитать только одно открытие. Открытие без подходящего
уведомления также не будет автоматически засчитано. Поправляйте такие случаи
клавишами F9/F10. Начало следующего матча отмечается вручную.

Сборка, 73 теста Core и опубликованные DLL проверены на Windows. Пользователь
подтвердил первую успешную серию 0.1.2: пять открытий дали +5 (6 → 11).
Точность всего матча, быстрые открытия и отсутствие повторов ещё нужно проверить.
В 0.2.0 добавлен график; распознавание и защита от повторов не изменены.

## Где хранится статистика

`%LOCALAPPDATA%\FortniteChestCounter\`

- `state.json` — события подсчёта, текущий матч и даты для дневной статистики.
- `settings.json` — область, язык, интервал и параметры счётчика.

Запись атомарная: счётчик обновляется после сохранения нового состояния.
Кнопка `−1` удаляет последнее событие текущего матча, даже если оно относится
к предыдущему дню. Перезапуск приложения сохраняет текущий матч.

## Статистика по дням

В главном окне нажмите **«Статистика по дням»**. Каждый столбец показывает число
сохранившихся открытий за один день, включая все матчи и ручные добавления.
Уже накопленная история появится автоматически: переносить или сбрасывать JSON не нужно.

- **7 дней / 30 дней** — последние календарные дни, включая сегодня.
- **Этот месяц** — с первого числа текущего месяца по сегодня.
- **Всё время** — с первого сохранённого открытия по сегодня.
- **Свой период** — выберите начальную и конечную даты в полях **«С» / «По»**;
  обе даты входят в период. Если начало позже конца, окно попросит исправить даты.

Над графиком показаны сумма за период и число дней с открытиями. Дни без открытий
не пропускаются и имеют значение 0. Наведите курсор на столбец для точной даты
и числа; длинный период прокручивается по горизонтали полосой прокрутки или колесом мыши.
Открытое окно обновляется при новых зачётах и ручных поправках. Отмена `−1`
уменьшает именно день удалённого события. Просмотр и выбор периода не изменяют историю.

## Если OCR не запускается

Проверьте, что рядом с EXE есть папки `x64` и `tessdata`, и что вы запускаете
приложение из распакованной папки, а не внутри ZIP.

Нативные библиотеки Tesseract используют **Microsoft Visual C++ Runtime x64**,
который обычно уже установлен вместе с играми. Если приложение сообщает,
что DLL OCR не загружаются, установите официальный Redistributable:

<https://aka.ms/vs/17/release/vc_redist.x64.exe>

## Сборка из исходников

Для полного переносимого комплекта начните с `START-HERE.md` в корне исходников.
Технические решения описаны в `docs/DESIGN-DECISIONS.md`, а работа на Windows —
в `docs/WINDOWS-DEVELOPMENT.md`. Решение IDE: `FortniteChestCounter.sln`.

Нужен **.NET SDK 10**. В PowerShell из папки проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build.ps1
```

Скрипт проверяет две модели из `tesseract-ocr/tessdata_fast`, выполняет
тесты, публикует самостоятельную сборку Windows x64 и создаёт архивы программы
и всего проекта. Также доступны `Build.cmd`, `Test.cmd` и `Diagnostics.cmd`.

Отдельные команды, также доступные на Linux с .NET SDK 10:

```text
dotnet test tests/FortniteChestCounter.Tests/FortniteChestCounter.Tests.csproj -c Release
dotnet publish src/FortniteChestCounter.Windows/FortniteChestCounter.Windows.csproj -c Release -o dist/FortniteChestCounter
python3 tools/package.py
```

Перед публикацией в `assets/tessdata` должны находиться `eng.traineddata`
и `rus.traineddata`; модели и тексты лицензий входят в подготовленные исходники.
