## Задача пользователя

Считать открытые сундуки Fortnite во время игры на ПК с Windows. Пользователь
попросил собрать исходники, ассеты и объяснения в одну переносимую папку,
чтобы продолжить работу и исправления на Windows.

## Текущее устройство

- Версия прототипа: 0.3.1 в исходниках и на GitHub; `dist` всё ещё содержит 0.2.0. C# / .NET 10, Windows Forms, Windows x64.
- Отдельное приложение захватывает выбранную область экрана через GDI.
- Tesseract 5.2.0 распознаёт `СУНДУК` / `CHEST` и начисление XP рядом.
- Модели `eng` / `rus` находятся в `assets/tessdata`; зависимости — в `assets/nuget`.
- `NotificationClassifier` проверяет текст и расположение строк.
- `NotificationGate` отделяет одно уведомление от следующего.
- `CounterLedger` атомарно сохраняет события в JSON.
- `dist/FortniteChestCounter` содержит готовую самостоятельную Windows-сборку.

## Работа с кодом

Сохраняйте разделение платформенной части `Windows` и чистой логики `Core`.
Не считайте успешную кросс-сборку доказательством работы захвата или OCR в игре.
Для изменения порогов распознавания нужны реальные кадры и результаты OCR.
Сохраняйте существующую пользовательскую статистику при любых исправлениях.

Пользовательские данные расположены в `%LOCALAPPDATA%\FortniteChestCounter`.
Отчёты `Diagnostics.cmd` и `Test.cmd` сохраняются в `diagnostics` внутри проекта.
Скрипты должны работать в Windows PowerShell 5.1 и с пробелами/кириллицей в пути.

## Проверки и сборка

Из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\test.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\package-workspace.ps1
```

На Linux с .NET SDK и PowerShell 7 те же PS1-скрипты запускаются через `pwsh`.
Режим `-Offline` в `build.ps1` / `test.ps1` использует только локальный NuGet feed.
Готовая программа предназначена для Windows; чистые тесты Core работают и на Linux.

При изменении зависимостей обновите lock-файлы через
`dotnet restore FortniteChestCounter.sln --force-evaluate`, затем выполните обычную сборку: скрипт обновит
`assets/nuget` из восстановленных пакетов. После изменения логики выполняйте
соответствующие тесты, затем публикуйте сборку и обновляйте документацию статуса.
