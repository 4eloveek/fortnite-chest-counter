# Контекст для продолжения работы

## Требования

Пользователь хочет считать открытые сундуки Fortnite **во время игры на Windows-ПК**.
После первого прототипа попросил перенести весь проект, ассеты и объяснения
в одну папку для самостоятельной работы и исправлений на Windows.

## Что реализовано

- Выбор монитора и области распознавания на замороженном кадре.
- OCR на русском / английском, проверка названия сундука и начисления XP.
- Фильтр яркого текста, выбор языка и интервала сканирования.
- Защита от повторного подсчёта одного уведомления.
- Счётчики текущего матча, дня и всех событий.
- Ручные `+1` / `−1`, начало нового матча, глобальные клавиши.
- Прозрачный для кликов оверлей с выбором угла экрана.
- Атомарная запись JSON-статистики, восстановление после перезапуска.
- Самостоятельная сборка Windows x64 с .NET, Tesseract и моделями.
- В 0.2.0 — столбчатый график открытий по дням, готовые периоды и выбор дат «с / по».

Подсчёт относится к экранным уведомлениям. Прототип не получает точный журнал
внутриигровых событий: фактическую точность нужно проверять на кадрах из игры.

## Статус

Первая сборка была создана на Linux с .NET SDK 10.0.402. Пройдены 33 теста
логики Core. Проверены публикация Windows x64 и комплектность архива.

Продолжение на Windows 10 x64, 23 ноября 2026:

- Пользователь установил SDK **10.0.404 x64**. **59 тестов Core пройдены на Windows**.
- Ошибка `CopyPixelOperation` (1087111200) исходной готовой 0.1.0 исправлена
  прямым `BitBlt`. **Исправление уже опубликовано в `dist`**, вместе с Runtime

  Подтверждены оконные флаги оверлея и исключение UI из захвата.

  освобождение ресурсов, 18 синтетических положительных OCR-примеров с фильтром
  и без него и 2 отрицательных примера. Статистика при этом не записывалась.

Живая диагностика выявила пропуск мелкой подписи СУНДУК в SparseText.

именем процесса: OpenCode больше не проходит только из-за заголовка проекта.
Обновление установлено с разрешения пользователя, JSON не изменены.
После установки 0.1.2 пользователь подтвердил первую живую серию: было 6,
открыл 5 сундуков, стало 11. Итог совпал; остальные режимы и точность всего
матча пока не измерены.

После сохранения работа возобновлена по новому запросу пользователя.
Следующий этап — три новых открытия с проверкой ровно одного зачёта на каждое,
затем быстрые открытия, Alt+Tab и дополнительные кадры. Сохранённый кадр нельзя
считать доказательством точности во всём матче. Подробности: [VERIFICATION.md](VERIFICATION.md).

## Для следующей итерации нужны

1. Кадр сразу после открытия обычного сундука с видимым начислением XP.
2. Кадры для других типов сундуков, если их тоже нужно учитывать.
3. Язык игры, разрешение, масштаб интерфейса и режим экрана.
4. Текст из поля диагностики и сведения о пропусках / двойных подсчётах.
5. Проверка нескольких быстрых открытий и поведения при Alt+Tab / паузе.

Кадры складывайте в `assets/samples`, технические отчёты — в `diagnostics`.
Требования к материалам описаны в `assets/samples/README.md`.

## Статистика по дням, 24 ноября 2026

Пользователь сообщил недоступность серверов после обновления Fortnite и попросил
добавить график дневных открытий с выбором периода. В **0.2.0** реализовано
отдельное окно «Статистика по дням»: 7 дней, 30 дней, этот месяц, всё время, свои даты.
Каждый день показан отдельно, включая нулевые; есть сумма периода, подписи чисел,
подсказки и горизонтальная прокрутка. История читается из прежнего `state.json`,
все матчи и ручные поправки учитываются; формат данных и распознавание не изменены.

Пройдены **73 теста Core** (14 новых) и **36 условий проверки UI** на тестовой
истории при DPI 96. Повторно прошли 23 условия захвата/OCR на опубликованных DLL.
Пользовательские JSON до изменений скопированы в `diagnostics/report-20261124-122538-244`;
их SHA256 после UI-проверок не изменились. С разрешения пользователя работающая
0.1.2 закрыта обычным способом; **0.2.0 опубликована в `dist`**, её DLL совпали
по SHA256 с проверенным кандидатом `diagnostics/daily-statistics-020/app`.
Повторная полная офлайн-сборка прошла 73 теста и создала оба архива. Финальная
копия JSON — `diagnostics/daily-statistics-020/before-install`; после публикации
хеши совпали. Replay прежних 98 кадров дал прежние 10 принятых и 0/11 ложных
на известных отрицательных. Настоящий матч после обновления игры сегодня не проверялся.

## Подготовка одного EXE для GitHub, 24 ноября 2026

Пользователь сообщил: «Ну вроде считает правильно, я проверил», затем попросил
однофайловую итоговую программу в отдельной папке для GitHub. Это общее
подтверждение пользователя без числа открытий, режима и измеренной точности.
Код подсчёта, OCR, схемы JSON и интерфейса в этой итерации не изменялся.

Добавлены профиль однофайловой публикации и `tools/build-release.ps1`.
Релиз **0.2.0** сохраняет тот же функционал, включая дневной график:
`release/v0.2.0-win-x64/FortniteChestCounter-v0.2.0-win-x64.exe`.
Все библиотеки, runtime, модели и лицензии находятся внутри файла; извлечение
в приватный временный кэш происходит автоматически. Нормальная `dist` и
работающая программа остаются прежними. Пользовательские данные не включаются
в EXE. GitHub-публикация не выполнялась. Инструкция: [GITHUB-RELEASE.md](GITHUB-RELEASE.md).

Итоговый EXE — около 58.0 MiB. Прошли 73 Core-теста и 67 проверочных условий
в самом self-contained процессе при первом запуске и повторном использовании
кэша, включая настоящий контрольный PNG и offscreen-отрисовку UI. Внешний
startup hook — только диагностический инструмент, не часть релиза. Существующая
программа не закрывалась; DLL dist и JSON сохранили прежние SHA256. Старая
пара ZIP оставлена без перепаковки: для GitHub предназначен новый EXE в release.

После уточнения пользователя туда же добавлен полный исходный проект. Теперь
`release/v0.2.0-win-x64` — комплект для GitHub, не папка только с одним файлом.
Код, тесты, модели, документация и build/config/lock-файлы присутствуют; EXE и
локальные nupkg не попадут в Git благодаря `.gitignore`. Пользователь выбрал MIT,
она включена в исходники и пересобранный EXE. Личные файлы исключены.
Успешны чистая офлайн-сборка полного комплекта и online restore/73 теста копии
без локальных пакетов. Инструкция находится в `UPLOAD-GITHUB.md` самого комплекта.

## Клавиша «+1» и быстрые открытия, 25 ноября 2026

Пользователь попросил разрешить назначать любую клавишу на добавление сундука
и исправить жалобу: при нескольких открытиях подряд засчитывается только одно.
Версия исходников — **0.3.0**; схема `state.json` не менялась.

- В Core добавлен `HotkeyBinding` (Win32-модификаторы + виртуальный код клавиши).
  `AppSettings.AddChestHotkey` по умолчанию `Ctrl+Alt+F9`, поэтому старые
  `settings.json` без нового поля загружаются с прежней клавишей.
- В главном окне кнопка с текущим сочетанием включает захват следующей клавиши.
  `Esc` отменяет; поддерживаются обычные клавиши, F-клавиши, стрелки, Tab, Enter.
  Сочетание без модификатора требует подтверждения. Занятые клавиши и
  `Ctrl+Alt+F7/F8/F10/F11/F12` отклоняются; при ошибке остаётся прежняя настройка.
  Новое значение сохраняется только после успешной регистрации.
- `NotificationGate.Observe(visible, signature, time)` различает уведомления по
  каноническому слову и положению (24 px). Первое появление требует 2 кадров,
  смена подписи — 3 кадров, отсутствие — 200 мс и 2 сканирований, минимум между
  зачётами — 700 мс. `visible` не даёт пропавшей строке XP снять блокировку.
- `OcrReader` возвращает `Visible`; `NotificationClassifier` строит подпись и
  умеет проверять наличие слова сундука без начисления.

Пройдены **88 тестов Core**, включая серию сменяющихся подписей, короткую паузу
между одинаковыми уведомлениями, мигание OCR, Alt+Tab/паузу, ручное подавление
и сохранение новой клавиши в JSON. Windows-проект компилируется на Linux с
`EnableWindowsTargeting`. Живой матч, реальные два быстрых открытия и захват
клавиши на Windows ещё не проверялись; нельзя утверждать, что исправление
подтверждено в игре. Остаточное ограничение: одинаковый текст в той же точке
без заметного исчезновения неотличим от одной длинной надписи.

Локально собран однофайловый EXE 0.3.0:
`release/v0.3.0-win-x64/FortniteChestCounter-v0.3.0-win-x64.exe`,
60 833 514 байт, SHA256 `65ae10...d4cf`. В папке также исходники, коммит и
тег `v0.3.0`. На GitHub релиз не публиковался, `dist` не заменялся.
## Ориентиры в исходниках

| Задача исправления | Файл |
| --- | --- |
| Не видит буквы, цвет или мелкий шрифт | `Windows/OcrReader.cs` |
| Видит текст, но не признаёт его сундуком | `Core/NotificationClassifier.cs` |
| Двойной подсчёт или пропуск при быстром открытии | `Core/NotificationGate.cs` |
| Настраиваемая клавиша «+1» | `Core/HotkeyBinding.cs`, `Windows/HotkeyCaptureButton.cs` |
| Неверные итоговые числа, сброс, сохранение | `Core/CounterLedger.cs`, `Core/JsonFile.cs` |
| Дневная история и выбор периода | `Core/CounterLedger.cs`, `Windows/StatisticsForm.cs` |
| Столбцы, подписи и прокрутка графика | `Windows/DailyChartControl.cs` |
| Окно, параметры, цикл сканирования | `Windows/MainForm.cs` |
| Чёрный захват или координаты | `Windows/ScreenCapture.cs`, `Windows/RegionSelectorForm.cs` |
| Оверлей, масштабирование, клики | `Windows/OverlayForm.cs` |
| Глобальные клавиши, проверка активного окна | `Windows/NativeMethods.cs`, `Windows/MainForm.cs` |

В таблице `Core` и `Windows` сокращают пути двух проектов внутри `src`.
