# Однофайловый релиз для GitHub

## Файл для загрузки

Готовый файл версии **0.3.1**, Windows x64:

```text
release/v0.3.1-win-x64/FortniteChestCounter-v0.3.1-win-x64.exe
```

Теперь эта же папка содержит полный комплект исходников для GitHub и один EXE.
Начните с её `UPLOAD-GITHUB.md`: код загружается в репозиторий, EXE — отдельно
в Releases. Пользовательские JSON и диагностические записи не включены.
Самому пользователю программы для работы по-прежнему достаточно только EXE.
В EXE включены приложение, .NET Runtime 10.0.15, Tesseract, Leptonica, обе OCR-модели,
README и тексты лицензий. Первое выполнение автоматически извлекает служебные
файлы в `%TEMP%\.net\<имя EXE без расширения>\<идентификатор сборки>`. При установленном
`DOTNET_BUNDLE_EXTRACT_BASE_DIR` используется указанный каталог.

Настройки и события хранятся отдельно в `%LOCALAPPDATA%\FortniteChestCounter`.
Обновление/перенос EXE и очистка служебного кэша не обнуляют историю. Программа
создаёт кэш сама; распространять его или папку `dist` вместе с EXE не требуется.

## Создать релиз

1. В нужном репозитории GitHub откройте **Releases → Draft a new release**.
2. Укажите тег **`v0.3.1`** и название **`Fortnite Chest Counter 0.3.1 · Windows x64`**.
3. Прикрепите указанный EXE как **release asset**, а не как файл исходников.
4. Добавьте описание ниже и при желании SHA256 из `diagnostics/release-*/SHA256SUMS.txt`.
5. Проверьте имя/версию файла и опубликуйте релиз вручную.

Релиз 0.3.1 опубликован 26 ноября 2026:
https://github.com/4eloveek/fortnite-chest-counter/releases/tag/v0.3.1.
Инструкция ниже нужна для повторной публикации будущей версии.

### Короткое описание для страницы релиза

> Счётчик экранных уведомлений об открытии сундуков Fortnite для Windows 10/11 x64.
> Один EXE со встроенными .NET, OCR и русской/английской моделями. Есть счётчики матча,
> дня и всех открытий, дневной столбчатый график с выбором периода, оверлей,
> ручные поправки, сохранение истории и переназначаемая клавиша «+1».
>
> Используйте оконный режим без рамки. Ctrl+Alt+F7 — выбор области с названием
> сундука и XP; Ctrl+Alt+F8 — старт/пауза; F9/F10 с Ctrl+Alt — +1/−1;
> Ctrl+Alt+F11 — новый матч; Ctrl+Alt+F12 — показать/скрыть оверлей.
> Клавишу «+1» можно переназначить кнопкой в главном окне.
>
> При первом запуске служебные файлы автоматически извлекаются в пользовательский
> временный кэш. .NET отдельно устанавливать не нужно. Если отсутствует Microsoft
> Visual C++ Runtime x64, установите официальный Redistributable:
> https://aka.ms/vs/17/release/vc_redist.x64.exe.
>
> Приложение не получает внутриигровой журнал: точность зависит от уведомлений и OCR.
> В 0.3.1 подпись уведомления сравнивается с допуском 12 px, поэтому дрожание OCR
> больше не сбрасывает подтверждения и одиночный сундук не пропадает. Быстрые
> открытия различаются по смене подписи и короткой паузе; если игра заменяет
> строку тем же текстом в той же точке без заметного исчезновения, она всё ещё
> может считаться одним уведомлением.
> Окно и оверлей намеренно исключаются из поддерживаемых способов захвата экрана.
> Это независимый проект, не официальный продукт Epic Games.

EXE не подписан сертификатом издателя. Windows SmartScreen может показать
предупреждение о неизвестном издателе; не заявляйте о наличии цифровой подписи.
Проверка 0.2.0 была проведена на текущем Windows-ПК с установленным Visual C++
Runtime. Для 0.3.1 выполнены 90 тестов Core и кросс-компиляция. Пользователь
проверил исправленную сборку в игре и сообщил, что она работает; количественная
точность всего матча и серия быстрых открытий не измерялись.

## Повторить сборку

В Windows PowerShell 5.1 из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\build-release.ps1 -Offline
```

Нужен .NET SDK 10. Профиль `SingleFile.pubxml` сохраняет структуру содержимого
при автоматическом извлечении: Tesseract нужны настоящие пути DLL и traineddata.
Это режим совместимости `IncludeAllContentForSelfExtract` .NET 10; при переходе
на будущий SDK его поддержку и загрузку OCR нужно проверять заново.

Скрипт выполняет Core-тесты, публикует в новую диагностическую staging-папку,
проверяет наличие ровно одного EXE и копирует его в папку версии внутри `release`.
Он не закрывает работающий счётчик, не обновляет `dist`, не меняет пользовательские
данные и не публикует ничего на GitHub. Посторонние файлы в целевой папке не удаляются.
Отчёт сборки, размер и SHA256 находятся в соответствующей папке `diagnostics/release-*`.
